==================================================
1. BUG UTAMA YANG HARUS DIPERBAIKI
==================================================

Saat pengguna memiliki pemasukan, misalnya:

Pemasukan:
Rp 900.000

kemudian pengguna ingin NABUNG,

aplikasi sekarang membingungkan karena tabungan tidak otomatis masuk ke data Tabungan kecuali pengguna memahami alur teknis:

Pengeluaran
→ Alokasi
→ Tabungan
→ Target

Saya TIDAK MAU pengguna harus memahami alur teknis tersebut.

Saya ingin menu TABUNGAN bekerja seperti aplikasi keuangan yang normal.

==================================================
2. ALUR TABUNGAN BARU
==================================================

Di halaman:

TABUNGAN

sediakan tombol utama:

+ TAMBAH SETORAN

Saat ditekan:

buka form khusus:

TAMBAH SETORAN TABUNGAN

Field:

- Tanggal
- Target Tabungan
- Nominal
- Catatan opsional

Button:

SIMPAN SETORAN

Pengguna TIDAK perlu memilih:

- Pengeluaran
- Alokasi
- Tabungan

secara manual.

Aplikasi yang mengurus pencatatan internalnya.

==================================================
3. JIKA BELUM ADA TARGET TABUNGAN
==================================================

Pengguna tetap harus bisa menabung.

JANGAN blokir pengguna hanya karena belum membuat target.

Sediakan otomatis:

TABUNGAN UMUM

sebagai target default/system target.

Contoh:

Tabungan Umum

Pengguna bisa langsung:

Tambah Setoran
→ pilih Tabungan Umum
→ masukkan nominal
→ simpan

Selain itu pengguna tetap dapat membuat target sendiri:

- Dana Darurat
- Liburan Keluarga
- Pendidikan Anak
- Rumah
- Kendaraan
- target custom lainnya

==================================================
4. TARGET TABUNGAN
==================================================

Halaman Tabungan menampilkan:

TOTAL TABUNGAN

contoh:
Rp 200.000

Kemudian:

Target Tabungan

Tabungan Umum
Rp 200.000

Dana Darurat
Rp 1.500.000 / Rp 5.000.000
30%

Liburan Keluarga
Rp 1.200.000 / Rp 2.000.000
60%

Gunakan progress bar untuk target yang memiliki nominal target.

Tabungan Umum tidak wajib memiliki target akhir.

==================================================
5. RIWAYAT TABUNGAN
==================================================

Di halaman Tabungan tampilkan:

RIWAYAT TABUNGAN

Contoh:

12 Okt 2026
Setoran Tabungan Umum
+ Rp 200.000

10 Okt 2026
Setoran Dana Darurat
+ Rp 100.000

Setiap setoran wajib langsung masuk ke Riwayat Tabungan.

Setelah aplikasi:
- ditutup
- force stop
- dibuka kembali
- perangkat restart

data tabungan HARUS tetap ada.

==================================================
6. SINGLE SOURCE OF TRUTH
==================================================

Jangan membuat database tabungan terpisah yang tidak sinkron.

Gunakan transaksi sebagai single source of truth.

Setoran tabungan harus menghasilkan transaksi internal dengan metadata:

allocation = "savings"

dan targetId sesuai target tabungan.

Tetapi detail teknis ini JANGAN ditampilkan kepada pengguna pada flow normal.

==================================================
7. PERHITUNGAN KEUANGAN — JANGAN DOUBLE COUNT
==================================================

Perbaiki perhitungan supaya tabungan tidak dihitung dua kali.

Gunakan model berikut:

Pemasukan
= seluruh transaksi income reguler

Pengeluaran
= HANYA pengeluaran reguler

Tabungan
= transaksi allocation = savings

Investasi
= transaksi allocation = investment

SALDO TERSEDIA:

Saldo =
Pemasukan
- Pengeluaran Reguler
- Setoran Tabungan
- Alokasi Investasi

Contoh:

Pemasukan:
Rp 900.000

Pengeluaran reguler:
Rp 0

Tabungan:
Rp 200.000

Investasi:
Rp 0

Maka:

Saldo tersedia:
Rp 700.000

Dashboard:

Pemasukan
Rp 900.000

Pengeluaran
Rp 0

Tabungan
Rp 200.000

Investasi
Rp 0

Saldo Bulan Ini
Rp 700.000

JANGAN menampilkan Pengeluaran = Rp 200.000 hanya karena pengguna menabung.

Setoran tabungan adalah ALOKASI,
bukan pengeluaran konsumtif.

==================================================
12. TABUNGAN UMUM SYSTEM TARGET
==================================================

Tabungan Umum harus dibuat dengan aman.

Jangan membuat duplikat setiap startup.

Gunakan stable ID khusus atau mekanisme system target.

Contoh internal:

system-general-savings

Tetapi jangan bergantung pada literal tersebut jika arsitektur sekarang memiliki solusi lebih baik.

Jika data lama tidak memiliki Tabungan Umum:

buat melalui migration/default-data yang aman.

JANGAN menghapus target tabungan lama pengguna.
